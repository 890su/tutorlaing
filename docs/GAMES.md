# Игры вдвоём и Telegram Mini App

Актуально на 2026-08-14. Игры — отдельный social-модуль: они не влияют на
учебные сессии, адаптивную сложность или напоминания.

## Как это работает

1. Пользователь открывает `Помощник → Игры вдвоём` или `/games`.
2. Telegram Mini App передаёт `initData`; сервер проверяет его HMAC, срок
   действия, alpha-access и согласие на приватность.
3. Игрок выбирает публичный только внутри игр ник (`a-z`, `0-9`, `_`, 3–24).
4. По нику создаётся приглашение. Соперник должен прежде открыть игры и
   выбрать ник, после чего принимает приглашение в Mini App.
5. Каждый ход проверяется сервером. Polling интерфейса только обновляет экран;
   он не является источником истины.

## Контракты модулей

| Модуль | Контракт | Ответственность |
|---|---|---|
| `game_service.py` | `GameDefinition`, `GameStore` | Валидация ника, приглашение, ход и публичная проекция игры |
| `storage.py` | owner-scoped game methods + `version` | SQLite-состояние, условная транзакционная запись и event history |
| `games_web.py` | `GET /games`, `POST /games/api/*` | Проверка Mini App identity и HTTP-ошибки без SQL/rules |
| `games/app.js` | API client + render | Telegram-theme UI, polling, действия пользователя |

`games.version` предотвращает двойной ход при одновременных запросах: запись
удаётся только если версия, прочитанная игроком, всё ещё актуальна.

## Добавление следующей игры

1. Добавьте `GameDefinition` в `game_service.py` и зарегистрируйте его в
   `GAME_REGISTRY`.
2. Опишите минимальное JSON state и чистую функцию `move(state, marker,
   position)`. Она не делает SQL и не доверяет клиенту.
3. Добавьте адаптер отображения в `games/app.js`; серверный API и приглашения
   уже общие для всех игр.
4. Добавьте тесты правил, права игрока, гонки версии и Mini App API.

Не используйте Telegram `username` как идентификатор: он может отсутствовать и
меняться. Игровой ник намеренно отдельный и доступен только участникам игр.
