# Игры вдвоём и Telegram Mini App

Актуально на 2026-08-14. Игры — отдельный social-модуль: они не влияют на
учебные сессии, адаптивную сложность или напоминания.

## Как это работает

1. Пользователь открывает `Помощник → Игры вдвоём` или `/games`.
2. Telegram Mini App передаёт `initData`; сервер проверяет его HMAC, срок
   действия, alpha-access и согласие на приватность.
3. Если у игрока есть Telegram `@username`, он сохраняется только после
   проверки подписанного `initData` и используется как поиск соперника.
4. Игрок либо вводит настоящий `@username`, либо создаёт одноразовую ссылку.
   Ссылка ведёт в бот через стандартный `/start game_<token>`, который отдаёт
   Mini App уже с нужным приглашением. Она нужна, когда username отсутствует
   или соперник ещё не открывал игры.
5. Каждый ход проверяется сервером. Polling интерфейса только обновляет экран;
   он не является источником истины.
6. В активной партии `resign` завершает её победой соперника, а `finish` — без
   победителя. Оба перехода доступны только участникам активной партии и
   записываются в историю событий.

## «Дурак»: правила первого варианта

Это подкидной «Дурак» для двух игроков с колодой в 36 карт. Сервер тасует и
раздаёт карты, показывает козырь, хранит руки отдельно и возвращает клиенту
только руку текущего игрока и количество карт соперника. В раунде доступны:

- атака и подкидывание только картами рангов, уже лежащих на столе;
- отбивание старшей картой той же масти или козырем;
- «Взять карты», после чего атакующий может подкинуть подходящие карты;
- «Завершить раунд» после отбоя или решения взять карты; затем добор до шести.

После окончания колоды выигрывает тот, у кого первым не осталось карт.
Переводной режим не смешивается с этим набором правил: если будет нужен, он
станет отдельным `GameDefinition`/mode и отдельным UX-потоком.

На столе пользователь сначала выбирает карту в своей руке; при отбое затем
нажимает конкретную незакрытую карту атаки. Кнопки «Взять карты» и «Завершить
раунд» показываются только в разрешённом состоянии — это уменьшает число
ошибок и не подменяет серверную проверку.

## «Морской бой»: первый вариант правил

Это классическая партия для двух игроков на поле 10 × 10. Флот из десяти кораблей
расставляется сервером автоматически при создании приглашения: игрок сразу видит свой
флот и начинает игру, не проходя отдельный технический экран расстановки.

Mini App показывает две строго разные зоны: «Радар соперника» (туда можно стрелять)
и «Ваш флот». Во второй зоне видны собственные корабли, попадания и промахи; в первой —
только уже сделанные выстрелы и их результат. Расклад соперника, список его кораблей и
состояние его поля не передаются клиенту. Каждый выстрел приходит как `action=fire` с
координатой в `target`; сервер сверяет очередь, повтор клетки и результат, затем передаёт
ход сопернику или фиксирует победу после потопления всего флота.

## Контракты модулей

| Модуль | Контракт | Ответственность |
|---|---|---|
| `game_service.py` | `GameDefinition`, `GameStore` | Поиск по Telegram username, ссылочные приглашения, ход и публичная проекция игры |
| `storage.py` | owner-scoped game methods + `version` | SQLite-состояние, условная транзакционная запись и event history |
| `games_web.py` | `GET /games`, `POST /games/api/*` | Проверка Mini App identity и HTTP-ошибки без SQL/rules |
| `games/app.js` | API client + render | Telegram-theme UI, polling, действия пользователя |

`games.version` предотвращает двойной ход при одновременных запросах: запись
удаётся только если версия, прочитанная игроком, всё ещё актуальна.

## Добавление следующей игры

1. Добавьте `GameDefinition` в `game_service.py` и зарегистрируйте его в
   `GAME_REGISTRY`.
2. Опишите минимальное JSON state, player-scoped `public_state()` и чистую
   функцию действия (`move()` либо `action()`). Они не делают SQL и не доверяют
   клиенту.
3. Добавьте адаптер отображения в `games/app.js`; серверный API и приглашения
   уже общие для всех игр.
4. Добавьте тесты правил, права игрока, гонки версии и Mini App API.

Telegram `chat_id` остаётся единственным идентификатором и никогда не попадает
в клиент. `@username` — только обновляемый удобный индекс для приглашения; он
может отсутствовать или меняться. Ссылка содержит криптографически случайный
одноразовый token, действует 7 дней и становится недействительной после первого
получателя.
